# Shader support audit and validation

This folder records the render-surface audit, implementation, and runtime evidence for the 2.3.2 shader-support change. The release question is whether Ghost and Wraith remain recognizable under real shader packs. Using Minecraft's ordinary lighting path does not establish that visual result; the shader captures below are the visual evidence. The normal path stays as the fallback for vanilla and loaders without a compatible shader mod.

## Render-surface audit

The resource counts and alpha values below come from the 1.21.1 NeoForge assets. Entity PNGs are palette images; counts are after decoding to RGBA. The alpha counts describe source texels, before atlas/model sampling. “Normal entity lighting” describes the inputs passed by the mod's shader-aware renderer; an active shader pack transforms those inputs through its own render pipeline. It does not mean the final image uses vanilla lighting.

No additional eye-mask or particle-emission pass is enabled. The renderer predicate routes invisible, translucent, and outline/glowing cases through Minecraft's normal `getRenderType` handling so those entity states retain their native behavior. This also avoids changing the number of entity passes.

The 1.7.10 Forge client has distinct classic render code and is included in the surface audit. `RenderGhost` and `RenderWraith` use `RenderLiving` with their own alpha-textured models; Wraith enables standard alpha blending. Neither uses a separate full-bright pass or registers a custom particle renderer. The entities' `getBrightnessForRender` overrides now clamp block light to 10 only while OptiFine reports an active pack. Grenade and Sticky Dynamite use custom entity renderers, while the explosive and device item previews use Forge `IItemRenderer` geometry with their authored textures and normal item lighting. Ectoplasm/Soul Lantern has non-opaque bounds and emits level 12 light; Mining Charge has non-opaque bounds and no declared emission; Spectral Infuser emits level 13 only when lit. Remaining catalog blocks and item icons use the classic Minecraft block/item render paths. The 1.7.10 shader captures below directly verify Ghost and Wraith; these other classic surfaces were audited in source, so no claim of pack-by-pack visual coverage is made for each one.

## Recovery audit started October 4, 2026

The all-target release gate remains **incomplete**. The recovery work and fresh exact-runtime evidence are recorded in [recovery/README.md](recovery/README.md) and [recovery/acceptance-matrix.json](recovery/acceptance-matrix.json). Older capture sets below retain their original results; they do not certify a changed artifact, an alternate Forge pin, or an undocumented display/audio route.

The earlier availability research missed [ForgeOculus's documented Beddium dependency and archived build](https://www.curseforge.com/minecraft/mc-mods/forgeoculus), and [Oculus Community Port's 26.2 Forge beta](https://www.curseforge.com/minecraft/mc-mods/oculus-community-port). Neither should be described as an absent ecosystem until these candidates have been evaluated. Fresh pinned Forge 52.1.10 runs now complete the 12 scenes with OptiFine J1 and with ForgeOculus 1.8.8/Beddium 1.0.11. The latter also passes shader off/on checks. Normal menu entry resolved the earlier Quick Play initialization failures; the snapshot-only workaround was removed before these successful runs. The 26.2 community port is a limited full-screen shader beta, so its existence alone does not establish full world/entity shader support.

## Earlier runtime coverage and loader research (superseded where recovery evidence exists)

The shader-aware renderer change applies to modern Forge and NeoForge targets from 1.20.1 onward and all 26.x loaders. Fabric 1.20.1, 1.20.2, and 1.21.1 already used Minecraft's normal lit entity path. Minecraft 1.7.10 retains its classic renderer, but its Ghost and Wraith now supply a minimum block-light value only while OptiFine reports an active shader pack. Those facts describe code paths only; they do not predict how a particular shader pack renders the models.

Shader loader support varies by Minecraft version and loader. The table distinguishes a loader combination that can be attempted from one where no compatible shader loader was available in this audit. `Iris` entries use Iris (and Sodium where required); `Oculus` 1.20.1 requires Embeddium; ForgeOculus 1.21.1 requires Beddium. `OptiFine` is a separate shader implementation. A `—` means no viable matching shader loader was identified for this target, not that the mod itself is unsupported there.

The expanded `scripts/smoke-client.py --spectral-render-check` scene captures both entities at noon and midnight, during rain, against dark and bright backdrops, and inside a lit room. It checks world entry, each scene command, and clean client exit. The default launch uses isolated software-rendered Xvfb; any `--display` override must also be verified as an isolated agent-owned virtual display under `AGENTS.md`. `--disable-shaders` stages Iris and Sodium with `enableShaders=false`; omitting shader-loader arguments covers the no-loader baseline. Pass different `--shader-pack` archives to exercise active packs. `--retain-spectral-entities` moves each test entity out of view after its captures rather than removing them; this is available to get visual evidence when a shader runtime crashes while flushing an entity removal, and such a run does not replace the separate removal/crash check. `--visual-showcase` adds Ectoplasm Lantern and Mining Charge captures to shader runs.

Each output directory contains the smoke JSON/log and PNG captures. The JSON records exact target, client mod jar names, pack name, display, shader-load result, and whether scene commands passed. Retain failed runs alongside successful evidence so a pack load or scene failure is not mistaken for render validation.
